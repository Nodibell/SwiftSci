# SwiftSci 3.13.0 Accuracy & Numerical Parity

> [!NOTE]
> **Provenance Clarification (`v3.13.0`)**: There is **no independent `3.13.0` classical/standardized run directory** in `Benchmarks/Runs/`. Because `v3.13.0` modified only `SwiftLLM` and `SwiftNLP` (upstream `mlx-swift 0.33.0`, packed 4-bit/8-bit loading, binary parser bounds, and serialized embeddings) without changing `SwiftDataFrame`, `SwiftStats`, `SwiftPreprocessing`, `SwiftForecast`, or classical `SwiftML` hot paths, all classical and tabular parity records below **carry forward the audited `v3.12.0` baseline unchanged**.

> [!WARNING]
> **v3.13.2 Historical Audit Notice**: Legacy `--research` entries below came from retired runners (`SwiftSciBenchmarks --research`, `Benchmarks/Python/accuracy_benchmarks.py`) removed in `v3.13.2`. Additionally, `v3.13.2` clarified that `ExponentialSmoothing` minimizes SSE (not Gaussian likelihood), `ARIMAModel` uses Hannan-Rissanen OLS (with G-033/G-037 defects fixed in `v3.13.2`), and `TreeSHAP` supports DecisionTree/RandomForest regressors only (G-035/G-036).

Numerical parity compares SwiftSci `3.13.0 / 3.12.0` (Swift 6, Accelerate BLAS/LAPACK, Metal & MLX `0.33.0`) against Python references (**NumPy 2.5.3**, **Pandas 3.0.6**, **Scikit-Learn 1.8.0**, **SciPy 1.18.1**, **Statsmodels 0.14.6**, **NLTK 3.10.3**, **SHAP 0.46.0**, **PyTorch 2.11.0**).

## Correctness & Mathematical Enhancements in 3.13.0

| Subsystem | Prior Behavior (`3.12.0`) | `3.13.0` Enhancement | Mathematical & Protocol Impact |
| :--- | :--- | :--- | :--- |
| **Native Packed Quantized LLM (`SwiftLLM`)** | `SafeTensorsParser` lacked unsigned dtypes (`U32`) and `loadWeights` loaded dense weights only. | Added `U8`/`U16`/`U32`/`U64`/`I16`/`BOOL` SafeTensors parsing, `AffineQuantizationConfig` + `loadQuantizedWeights`, auto-detection in `loadWeights`, cross-shard split staging, and `ModelDownloader`. | Keeps packed 4-bit/8-bit weights in `QuantizedLinear` / `QuantizedEmbedding` within **$\Delta < 10^{-3}$** vs dequantized Float16/Float32 dense models and bit-identical sharded vs single-shard logits. |
| **Binary Parser Bounds (`SwiftLLM`)** | `SafeTensorsParser` lacked shape/byte validation before `MLXArray`; `GGUFParser` read bool metadata as 4 bytes without array/offset bounds. | Enforced overflow-checked non-negative shape & payload byte-count validation in `SafeTensorsParser` and 1-byte bool + header/array/tensor bounds in `GGUFParser`. | Malformed or hostile files throw `SwiftMLError.invalidInput` cleanly without trapping or multi-billion-iteration loops. |
| **Embeddings & Tokenizers (`SwiftNLP`)** | `AppleSentenceEmbeddingEngine.embedBatch` ran concurrent `NLEmbedding` lookups; `BPETokenizer` rejected bare `ByteLevel` `post_processor`. | Serialized `embed(_:)` with `NSLock` + sequential cancellable `embedBatch`, and accepted bare `ByteLevel` `post_processor` with `<|begin_of_text|>` validation. | Eliminates `SIGSEGV` crashes on $> 16$ batch embeddings and supports community MLX Llama 3 tokenizer exports. |

### Scope Boundaries & Methodology Caveats

- **Shared Binary Inputs**: Legacy `--research` fixtures used `BenchmarkLCG` for identical IEEE 754 binary64 inputs; identical inputs do not guarantee bit-identical intermediate decompositions across different solvers.
- **Pre-`v3.13.2` Scope**: Pre-`v3.13.2` ARIMA/SARIMA (G-033, G-037) and TreeSHAP (G-035, G-036) scope boundaries apply to `3.13.0`; see [`ACCURACY/3.13.2.md`](3.13.2.md) for current validation.
